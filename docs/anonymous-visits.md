# Anonymous visit counts

The site makes one best-effort count request per browser tab session. A boolean in `sessionStorage` is set before the request, so rerenders, same-tab navigation, reloads, and retries do not send another count in that session. If storage is unavailable or the request fails, the visit can be missed; the client does not retry. These are approximate tab sessions, not guaranteed distinct people. Separate tabs or devices can count separately, and direct automated requests can inflate totals.

The collector stores only daily aggregate counts grouped by UTC date, Vercel country code, and coarse first-level region code. Missing or malformed geography is grouped as `unknown`. It stores no per-visit event, URL, query string, referrer, name, email, IP address, user agent, cookie, or persistent tracking ID. The browser session flag is local and temporary.

On production Vercel, country and first-level region are read from Vercel's `x-vercel-ip-country` and `x-vercel-ip-country-region` request headers. Vercel documents these as IP-derived location values and cautions that an upstream proxy can make the location describe that proxy; the result is approximate. Geography is recorded only when both Vercel production markers and the existing remote database URL/token are configured. The collector is a no-op on local and preview deployments and when remote database credentials are absent. [Vercel request headers](https://vercel.com/docs/headers/request-headers) · [Vercel system environment variables](https://vercel.com/docs/environment-variables/system-environment-variables) · [Vercel proxy guidance](https://vercel.com/kb/guide/can-i-use-a-proxy-on-top-of-my-vercel-deployment).

The first enabled collector request creates the isolated `anonymous_daily_visits` aggregate table in the configured database. The existing database credentials must allow table creation, inserts, and aggregate reads. Daily aggregate rows remain in the database until an owner removes them. No production migration or deployment is part of this source change.

Owners can read totals with `npm run report-visits` in an environment configured with the same `DATABASE_URL` and `DATABASE_AUTH_TOKEN` as the database. The command prints only total, UTC-day, and country/region aggregates. With no configured database it uses the app's local SQLite default, which is separate from production.
